# StateMotion development installation

This package contains a UXP development panel. The native Windows effect must be
rebuilt separately; the panel ZIP is not a consumer installer or a native binary.

## Development prerequisites

- Node.js 24 and npm, using the committed package lockfile.
- A C++17 compiler for SDK-free checks; GCC 14.2 was used on Linux.
- Premiere Pro 26.3 or later and Adobe UXP Developer Tool for desktop validation.
- Windows native build: Visual Studio C++ Build Tools with the v142 toolset,
  Windows SDK, and the official Adobe After Effects Effect SDK installed outside
  the repository. The current repository has a Windows MSBuild project; it does
  not contain a supported macOS native build.

## Build and verify

From the repository root:

```sh
npm --prefix src/statemotion/panel ci
node tools/verify-development.mjs
node tools/package-panel.mjs
```

The verifier executes contract checks, TypeScript progress tests, every SDK-free
C++ suite, panel typecheck/tests/build, package integrity/reference checks, and
validation-runner tests. A failed child command returns a failing exit code.
Current-run logs and the summary path are printed under `build/verification/`.
The archive is `dist/statemotion-panel-dev.zip`, containing `manifest.json`,
`index.html`, `dist/main.js`, and `dist/main.css`. Packaging checks references and
uses fixed ZIP metadata for reproducibility. No native binary is included.

## Build the native Windows effect

Open an **x64 Visual Studio developer command prompt** at the repository root.
Install the v142 C++ toolset and Windows SDK, and keep the official Adobe SDK
outside the checkout:

```bat
set "STATEMOTION_SDK=<SDK_ROOT>"
node tools/build-native.mjs --check
node tools/build-native.mjs
```

`<SDK_ROOT>` must contain `Examples\Headers`, `Examples\Resources` and
`Examples\Util`. Do not copy proprietary SDK files into this repository.
If MSBuild is not on PATH, set `STATEMOTION_MSBUILD` to its full **MSBuild.exe**
path, without adding command arguments. The runner passes paths as arguments,
including SDK/repository paths containing spaces.

Preflight returns a nonzero exit code for unsupported operating systems, missing
SDK files or unavailable compiler/MSBuild. It checks tool availability; the build
itself verifies the installed toolset and Windows SDK can compile this project.
It does not download the proprietary SDK, install software or modify MediaCore.

The runner checks generated bindings and invokes a Release/x64 **Rebuild** into a
new `build/native-validation/run-*/bin/` directory. Only that run's AMD64 PE DLL
`StateMotion.aex` can be accepted. Failed builds keep logs and failed evidence;
old output elsewhere cannot count as success. PiPL preprocessing also stops at
the first failed step.

Each run retains `contract.log`, `build.log` and `evidence.json` (commit, dirty
source flag, tool output, SDK file hashes, binding contract and native SHA-256).
Successful builds additionally generate `host-checklist.md` with every desktop
gate untested. SDK hashes identify build inputs; record the SDK product version
manually. Build success does **not** certify plugin loading or exported frames.

Close Premiere before replacing its installed binary. Install exactly one copy
of the newly built AEX under the Windows Adobe MediaCore plugin location
`%ProgramFiles%\Adobe\Common\Plug-ins\7.0\MediaCore\`; this may require
administrator permission. Verify the **installed** file's SHA-256 equals
`evidence.json`, using PowerShell `Get-FileHash -Algorithm SHA256 <AEX_PATH>`.
Keep the matching panel and native build together. See the
[desktop smoke procedure](v0.1-alpha-desktop-smoke.md) for the first host run.

## Load the panel

1. Extract the development ZIP into a dedicated folder, or use
   `src/statemotion/panel` after building it.
2. In Adobe UXP Developer Tool, add the plugin by selecting **manifest.json**.
   The manifest's entry file is `index.html`; do not point the tool at the JS bundle.
3. Launch Premiere Pro 26.3+, then load the plugin and open StateMotion's panel.
4. Open About and check the product and binding versions. Apply an original
   bundled preset to a selected video clip, then inspect/edit A/B parameters.

The manifest uses Adobe's documented schema 5 and host ID `premierepro`.
User-initiated preset pickers require `localFileSystem: request`; copying the
non-sensitive debug report requires the documented clipboard permission. The
plugin requests no network access.

## Compatibility and release gates

Binding revision **5**, still 70 parameters, corrects native one-based popup
encoding and new-instance angle defaults. Canonical preset enums remain zero-based.
Existing projects with older binding metadata retain their previous native popup
interpretation and are read-only to the current panel. Keep a backup project and
use a newly created current effect for writable editing; this release does not
silently migrate an existing project effect. Supported historical preset files
(including revision 4 / 70 parameters) migrate to the current canonical contract
when imported; unknown future revisions are rejected and original files preserved.

SDK-free tests and a browser with a fake host do not establish Premiere behavior.
The rebuilt native effect must pass `v0.1-alpha-test-checklist.md`, including the
previous `AEVideoFilter:11` regression, point-unit round trips, popup labels,
persistence, undo/redo, timing after trims, alpha formats, FX and export. Record
operator evidence in `v0.1-alpha-host-status.md` before closing release gates.
