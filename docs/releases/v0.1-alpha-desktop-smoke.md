# First desktop smoke test

Use this procedure after a successful `node tools/build-native.mjs` on Windows.
The current Linux cloud cannot run MSBuild or Premiere. The runner's toolchain
regression tests use explicitly simulated Windows processes, not an Adobe SDK.

## Prepare the run

1. Close Premiere and build the current source from an x64 Visual Studio developer prompt as described in [installation](v0.1-alpha-installation.md).
2. Record the generated run directory. Prefer a clean Git tree; if `source.dirty` is true, preserve the exact diff as part of the evidence before claiming reproducibility.
3. Install the new `bin/StateMotion.aex`, keep only one installed copy and compare its SHA-256 with `evidence.json`.
4. Build/package the matching panel, then load its `manifest.json` in UXP Developer Tool. Record the panel ZIP SHA-256, Premiere version and SDK version in this run's `host-checklist.md`.
5. Use a new disposable Premiere project with a five-second video clip and a still containing transparent edges. Preserve any older compatibility project as a separate copy.

## Run the core workflow

- At 1920×1080, confirm the effect is discoverable and a new instance reports binding revision 5 and 70 parameters. Verify every popup label matches the selected value.
- Apply a moving bundled preset. Scrub start/middle/end and record expected versus actual position, scale, rotation and opacity. Apply another preset with fewer explicit values; confirm old crop/stroke/glow/manual state is reset.
- Edit A/B position, nonuniform scale, angle, anchor and opacity. Confirm point coordinates do not jump, colors round-trip and editing one control leaves unrelated values unchanged.
- Exercise spring overshoot, custom easing and manual mode; then swap A/B. Test undo/redo for apply, edit, swap and remove. Record whether each operation is atomic.
- Apply to two compatible selected clips. Change selection while an operation is preparing; confirm the operation reports failure and commits no staged edits. Do not infer this from a successful ordinary apply; record a reproducible interruption or leave the item untested.
- Enable stroke/gradient, glow, shadow and motion blur on transparent edges. Check for clipping, corrupt/black frames and the historical `AEVideoFilter:11` failure. Capture the relevant frames and any console errors.
- Repeat relevant checks at 1080×1920 and UHD, with trimmed, reversed and speed-adjusted clips and a freeze frame. Verify supported 8/16-bit worlds; mark unsupported formats explicitly rather than marking them passed.
- Save, close and reopen the project. Confirm settings/rendered motion persist. Export a short sequence and compare start/middle/end frames with the timeline at those exact times.
- In a copy of an older project, confirm legacy effects remain read-only and retain their previous interpretation. Import a supported revision-4 preset into a new current effect; reject an unsupported future revision.

## Preserve evidence

Fill the generated checklist with actual results, operator/date, host version,
installed hash and screenshot/log/export paths. Use **FAIL** for a reproduced
failure and **NOT YET TESTED** for an unexecuted or unobservable case. Do not mark
an entire section passed from a single sample. Attach the project and footage
only when permitted to share them; private local paths need not be committed.

Record failures with trigger, expected/actual behavior, binding revision and
minimal reproduction. Keep build logs and evidence next to that run. Update
[host status](v0.1-alpha-host-status.md) only from these observed results. Open
[release gates](v0.1-alpha-release-gates.md) stay open until corresponding desktop
evidence exists; SDK-free tests and binary header checks cannot close them.
